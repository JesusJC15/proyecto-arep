AREP

Plataforma academica de triaje con RAG trazable

Entrega final integral: demo reproducible, blueprint AWS y paquete academico

Problema

La orientacion inicial en salud necesita triage claro, evidencia recuperable y supervision humana en casos de mayor riesgo.

Propuesta

  • Portal paciente y espacio profesional
  • Triage por reglas con escalamiento
  • RAG semantico local, trazable y evaluable
  • Demo reproducible con Docker Compose

Arquitectura

  • Frontend React
  • Backend FastAPI con JWT, auditoria y metricas
  • Postgres como base oficial de demo
  • Corpus curado + indice RAG reproducible

Flujo de demo

  1. Paciente inicia sesion
  2. Crea consulta y ejecuta triage
  3. Recibe recomendacion con evidencia, score y rank
  4. Profesional toma el caso y lo revisa

RAG y trazabilidad

  • Corpus versionado con manifiesto curatorial
  • Chunking reproducible
  • Embeddings locales por defecto
  • Score, rank, metodo y razon de recuperacion por fuente

Resultados

  • Backend tests y E2E automatizado
  • Top-1 hit: 2/3
  • Top-k hit: 3/3
  • Observabilidad operativa: health, ready, metrics, rag/status

Entrega final

  • Dockerfiles + docker-compose oficial
  • Runbook y guion de demo
  • README maestro fuerte
  • Blueprint AWS base para red, app y datos

Limites

  • No es un sistema clinico productivo
  • No hay despliegue real en AWS en esta fase
  • No hay validacion clinica formal
  • FHIR sigue siendo proyeccion

Roadmap

  • Vector store productivo o pgvector
  • Secret management y hardening
  • Despliegue cloud real
  • Validacion con expertos y usuarios
